# Nawigacja i zbiorcza strona usług

- `/uslugi/` prezentuje wszystkie sześć usług, z istniejącymi kartami i opisami z zatwierdzonych tekstów CMS. Wykorzystuje dotychczasowy layout, typografię i wspólne CTA. Okruszki szczegółów usług prowadzą do tej strony zamiast sekcji strony głównej.
- W nagłówku nazwy „Usługi” i „Realizacje” są zwykłymi linkami do stron zbiorczych. Rozwinięcie nie przechwytuje kliknięcia nazwy. Na desktopie nie wyświetlamy strzałek; stan podmenu przekazują `aria-expanded`/`aria-controls` na linku. Na mobile rozwinięciem steruje osobny przycisk.
- Na desktopie podmenu otwiera się po najechaniu jako pełnoszerokie megamenu pod nagłówkiem. Duże linki usług/kategorii, odbiorcy oferty i skróty są ułożone w trzech kolumnach. Panel obejmuje cały viewport, także powyżej szerokości 1920 px, bez poszerzania dokumentu. Tło pod panelem jest przyciemniane i rozmywane przez CSS `backdrop-filter: blur(10px)`. Warstwa jest ukryta poza stanem otwarcia; mobile nie uruchamia rozmycia. Brak wsparcia lub preferencja ograniczonej przezroczystości zachowuje samo przyciemnienie. Nie animujemy filtra. Dostępna jest też klawiatura: fokus na nazwie, strzałki w dół/górę do pierwszego/ostatniego linku, zwykły Tab, Escape z powrotem do nazwy kategorii. Kliknięcie poza menu, wyjście fokusu, Escape także po otwarciu samą myszą oraz przewinięcie strony zamykają rozwinięcie i usuwają warstwę tła. Podmenu pozostaje otwarte podczas przechodzenia myszą do jego zawartości.
- Tekst linków nawigacji zachowuje ten sam kolor po najechaniu, otwarciu menu i przejściu do kategorii. Fokus klawiatury nadal ma widoczny obrys.
- Menu usług zawiera sześć podstron, link „Wszystkie usługi”, strony odbiorców oraz kontakt i serwis. Menu realizacji korzysta z istniejących kategorii oraz adresów `/realizacje/?kategoria=…`; prowadzą do przefiltrowanej listy, a nie nowych szablonów lub sztucznych projektów. Nazwa „Realizacje” otwiera pełną listę.
- Na telefonie i tablecie każde podmenu otwiera osobna strzałka. Nazwy nadal nawigują bezpośrednio. Zachowano „Strona główna” oraz brak przycisku „Darmowa wycena” w dialogu menu. Escape najpierw zamyka rozwinięcie, kolejny zamyka dialog i przywraca fokus. Rozwinięte menu może przewijać się pionowo.
- Bez JavaScriptu desktop zachowuje linki i rozwijanie CSS po hover/fokusie. Interaktywne przyciski pojawiają się dopiero po inicjalizacji skryptu. Nawigacja nie wymaga biblioteki, zapytań API, obrazów ani animacji; HTML jest generowany statycznie. Wszystkie adresy respektują `BASE_URL` dla GitHub Pages.

Scenariusze `tests/browser/navigation.spec.mjs` sprawdzają hover i przejście do podmenu, zwykłe kliknięcia nazw, klawiaturę i Escape, rzeczywiste linki do usług i kategorii realizacji, menu 320/390/834/1099 px, desktop 1100/1280/1440/1920/2560 px, brak poziomego przewijania i desktop bez JavaScriptu oraz kliknięcia dotykowe w kontekście z `hasTouch`. Zrzuty do kontroli wizualnej można zapisać przez `NAVIGATION_SCREENSHOTS=1` w ignorowanym katalogu `outputs/`.

Walidacja lokalna: Astro/TypeScript 100 plików, 0 błędów/ostrzeżeń; statyczny build 72 stron; 5 scenariuszy Playwright zaliczonych, obejmujących także rzeczywisty styl rozmycia, usunięcie warstwy po zamknięciu i preferencję ograniczonej przezroczystości. Zrzuty strony usług i podmenu sprawdzono na desktopie oraz mobile. Skrypt nawigacji pozostaje inline — bez dodatkowego żądania sieciowego. Nie jest to pełny ponowny pomiar Lighthouse ani test fizycznego Safari/iPhone.
